# Личные финансы

Консольное приложение для учёта доходов, расходов, бюджетов и
переводов между пользователями.

## Сборка и запуск

Нужны JDK 25 и Maven. Выполните из корня проекта.

~~~shell
mvn verify
java -jar target/finances.jar
~~~

В IntelliJ IDEA можно запустить класс `me.slkuni.Main` из корня проекта.
Приложение читает `config.yaml` из рабочей папки. Путь к данным задаётся
параметром `storage.file`.

~~~yaml
storage:
  file: data/state.json
~~~

## Первый сеанс

Выберите пункт меню по номеру и заполните поля по подсказкам.

1. На экране "Аккаунт" выберите **1. Создать аккаунт**, введите логин и пароль.
   Затем выберите **2. Войти** и введите те же данные.
2. В кошельке откройте **1. Операции**. Выберите **1. Добавить доход**,
   затем **Создать категорию**. Введите название категории и сумму.
   Аналогично через **2. Добавить расход** можно создать категорию расходов.
3. Вернитесь в кошелёк и откройте **2. Мои категории**. Выберите категорию расходов,
   затем **Установить бюджет** и введите 4000. Здесь же можно
   переименовать категорию, изменить или снять её бюджет.
4. Вернитесь в кошелёк, откройте **3. Отчёты** и выберите
   **1. Сводка за всё время**. В сводке будет показаны доход, расход
   и остаток бюджета.
5. Вернитесь в кошелёк и выберите **0. Сохранить и выйти**.

В обязательных полях пустой Enter отменяет ввод. Значения `0`, `00`
и пароли из нулей вводятся буквально. В поле бюджета `0` задаёт
нулевой лимит. В меню `0` возвращает назад.
Пустая дата операции означает сегодняшний день. Логин принимает
латинские буквы, цифры, дефис и
подчёркивание. Регистр логина и названий категорий при поиске игнорируется.
Суммы принимают точку или запятую, до двух знаков после разделителя.
Сумма операции должна быть положительной. Лимит может быть нулевым.

## Экраны

| Экран | Доступные действия |
| --- | --- |
| Аккаунт | Регистрация, вход |
| Кошелёк | Переходы в разделы, выход из аккаунта |
| Операции | Добавление дохода или расхода, перевод по логину |
| Мои категории | Список, создание и выбор категории для управления |
| Категория | Переименование, удаление категории без операций, управление бюджетом расходов |
| Отчёты | Сводка, фильтры по категориям и датам, вывод в терминал или файл |
| Снимки кошелька | Экспорт и импорт JSON-снимка |

Вложенное меню возвращает назад по пункту **0**. На экране "Аккаунт"
или "Кошелёк" этот пункт сохраняет данные и завершает работу. Конец ввода
также сохраняет данные.

В отчёте несколько категорий можно выбрать по номерам через пробел,
например `1 3`. Пустое поле включает все категории. Даты включены в
период. Чтобы оставить диапазон открытым, пропустите одну из дат.
Номер вне списка вызывает ошибку с указанием этого номера.
Бюджеты действуют за всё время. В отчёте за период дата фильтрует суммы
операций, а остаток лимита учитывает все расходы выбранной категории.
Приложение предупреждает при расходовании 80% лимита, его исчерпании и
превышении, а также при нулевом или отрицательном балансе.

Для перевода нужен достаточный баланс. Приложение записывает расход у
отправителя и доход у получателя в служебные категории. Каждая операция
содержит логин второй стороны.

Импорт заменяет категории, бюджеты и обычные операции текущего кошелька
после проверки снимка. Снимок привязан к логину. История входящих
и исходящих переводов должна полностью совпадать с текущей, включая
порядок, суммы, даты, направление и логины участников. Если снимок
удаляет, добавляет или изменяет перевод, восстановление отклоняется
и кошельки сохраняют прежнее состояние. Экспорт и текстовый отчёт
создают новый файл по указанному пути.

## Архитектура и хранение

- `model` содержит аккаунт, кошелёк, категории и операции. Деньги хранятся
  как `BigDecimal`, баланс вычисляется по операциям.
- `config` загружает настройки через интерфейс `ConfigParser`. В
  `Main` используется `YamlParser`.
- `service` управляет авторизацией и переводами, строит сводки. Интерфейс
  `WalletStorage` позволяет подменять файловое хранилище в тестах.
- `FileStorage` читает файлы и атомарно сохраняет состояние.
  Интерфейс `FinanceParser` задаёт чтение и запись данных и снимков.
  `JsonFinanceParser` реализует JSON. Для другого формата
  можно передать свою реализацию в конструктор `FileStorage`.
- `ui.screen` содержит отдельные экраны. Каждый реализует
  `Screen.show()` и возвращает `ScreenId` следующего экрана.
  `ConsoleApplication` управляет переходами, обрабатывает ошибки
  и сохраняет данные при выходе. `ConsoleIO` отвечает за ввод и вывод.
  `Main` связывает компоненты через `initConfig`, `initStorage`,
  `initServices` и `initUI`.

В файле состояния хранятся хеши паролей MD5.

При запуске приложение загружает файл состояния, при успешном входе
восстанавливает из него кошелёк пользователя. Для перевода кошелёк получателя
подгружается по его логину. До завершения работы изменения находятся в
памяти. Один снимок содержит данные всех пользователей, поэтому обе стороны
перевода записываются вместе. Каталог блокируется на время сеанса.
Принудительное завершение процесса может привести к потере несохранённых
изменений.

## Тесты

~~~shell
mvn test
~~~

JUnit проверяет расчёты, фильтры, бюджеты, авторизацию, переводы, CLI
и восстановление после перезапуска. Отдельные сценарии проверяют запрет
изменения переводов при импорте, валидацию логина до запроса пароля,
повторное сохранение после ошибки записи и блокировку второго процесса.

## CI/CD

GitHub Actions отдельно запускает тесты, собирает JAR.
